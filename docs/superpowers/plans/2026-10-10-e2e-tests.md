# End-to-end tests Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Playwright tests that click through sign up via invite, add a person and share a space against the real backend and the built frontend, locally and as a fourth CI job (#132).

**Architecture:** A backend command `e2e_reset` prepares `folkbook_e2e` with two known accounts. Playwright starts the backend on :8010 and `vite preview` on :4180 (proxying `/api` to :8010), logs both accounts in once in a setup project, and runs every spec at desktop and phone size, one at a time.

**Tech Stack:** `@playwright/test` (Chromium), Django management command, psycopg, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-09-e2e-tests-design.md`

## Global Constraints

- Ports: backend **8010**, frontend preview **4180**. Database **`folkbook_e2e`**. Never reuse a running server (`reuseExistingServer: false`).
- `e2e_reset` refuses unless the database name ends in `_e2e`.
- Accounts: **Ela Yılmaz** `ela@e2e.test` (admin), **Deniz Kaya** `deniz@e2e.test` (member). Password from `E2E_PASSWORD`, default `e2e-pass-123`.
- Projects: `desktop` 1280×900; `phone` 390×844 with `isMobile` and `hasTouch`. Chromium only. `workers: 1`. `trace: 'retain-on-failure'`. Retries: 0 locally, 1 in CI.
- Tests find things by role, label or visible text only: no CSS selectors, no test ids, no `waitForTimeout`. Every name a test creates carries a random suffix (e.g. `Greta 4821`), so tests don't depend on order or on a fresh database.
- The dev setup is unchanged: the proxy target defaults to `http://localhost:8000`.
- No new dependency besides `@playwright/test` (say why in the commit body).

## Review Focus

1. **The reset hits the dev book.** A `.env` with `POSTGRES_DB=folkbook` must never win over the `folkbook_e2e` Playwright passes. uv keeps variables already in the environment over the file's; the refusal is the backstop. Task 1 tests the refusal. Task 2's run checks the command's own output: `Reset folkbook_e2e.`.
2. **A retry in CI runs on a database that already holds the first try's data.** Assertions name the test's own unique people and spaces. They never count rows ("1 space"), and never expect an empty list except in the newcomer's fresh book. Tasks 2–4 follow this.
3. **One name matches twice on phones.** Desktop and phone controls both exist in the page (`md:hidden` / `hidden md:flex`), and a keyboard hint can join a button's name ("Add person N"). Locators must match exactly one visible element in both projects. Every spec runs in both projects (Tasks 2–4).
4. **A server is already on 8010 or 4180** (a forgotten dev run). Playwright must fail with "port in use", never test against it. `reuseExistingServer: false` and `--strictPort` cover this (Task 2).
5. **CSRF through the preview proxy.** Logging in through `vite preview` must keep the browser's Host header (`changeOrigin: false`, the same as dev), or every write gets a 403. The setup project logs in through the real page, so it catches this (Task 2).

### Task 1: `manage.py e2e_reset`

**Files:**
- Create: `backend/accounts/management/__init__.py`, `backend/accounts/management/commands/__init__.py`, `backend/accounts/management/commands/e2e_reset.py`
- Test: `backend/tests/accounts/test_e2e_reset.py`

**Ruling (spec deviation):** the spec puts the command in `backend/core/management/commands/`, but `core` isn't an installed app, so Django would never find it there. `accounts` is installed, and the command's real work is making accounts.

**Interfaces:**
- Produces:
  - `KNOWN_ACCOUNTS: list[tuple[str, str, bool]]`, with entries `(email, name, admin)`;
  - `create_known_accounts(password: str) -> list[User]`;
  - the command `e2e_reset`, which prints `Reset <name>.` on success and raises `CommandError` otherwise.

- [ ] **Step 1: Write the failing tests**

```python
pytestmark = pytest.mark.django_db

def test_refuses_a_database_not_named_for_end_to_end_tests():
    someone = UserFactory()
    with pytest.raises(CommandError, match="_e2e"):
        call_command("e2e_reset")   # pytest's database is test_folkbook
    assert User.objects.filter(pk=someone.pk).exists()

def test_makes_the_known_accounts_with_their_me():
    ela, deniz = create_known_accounts("e2e-pass-123")
    assert (ela.email, ela.display_name, ela.is_staff) == ("ela@e2e.test", "Ela Yılmaz", True)
    assert (deniz.email, deniz.display_name, deniz.is_staff) == ("deniz@e2e.test", "Deniz Kaya", False)
    assert ela.check_password("e2e-pass-123") and deniz.check_password("e2e-pass-123")
```

- [ ] **Step 2: Run them and watch them fail**

Run: `cd backend && uv run --env-file ../.env pytest tests/accounts/test_e2e_reset.py -v`
Expected: FAIL. The import fails, or the command is unknown.

- [ ] **Step 3: Implement `e2e_reset.py`**

`handle` does these steps in order:
1. Read the name from `connection.settings_dict["NAME"]`. If it doesn't end in `_e2e`, raise `CommandError("Refusing to reset <name>: e2e_reset only runs on a database whose name ends in _e2e.")`.
2. Create the database if it's missing. Use `psycopg.connect(dbname="postgres", …same user/password/host/port…, autocommit=True)`, check `pg_database`, and run `CREATE DATABASE` with `sql.Identifier`.
3. Run `call_command("migrate", verbosity=0)`, then `call_command("flush", interactive=False, verbosity=0)`.
4. Run `create_known_accounts(os.environ.get("E2E_PASSWORD", "e2e-pass-123"))`.
5. Print `Reset <name>.`.

`create_known_accounts` uses `User.objects.create_superuser` or `create_user(email, password, name=name)`, which also creates each Me. The module docstring says why the command exists and that it only ever touches `*_e2e`.

- [ ] **Step 4: Run them and watch them pass, then the whole backend suite and lint**

Run: `cd backend && uv run --env-file ../.env pytest && uv run ruff check . && uv run ruff format --check .`
Expected: all pass.

- [ ] **Step 5: Try it for real**

Run: `cd backend && POSTGRES_DB=folkbook_e2e uv run --env-file ../.env python manage.py e2e_reset` twice: once with no `folkbook_e2e` database, then again.
Expected: both print `Reset folkbook_e2e.`. The first run creates the database.

Then run it without the override: `uv run --env-file ../.env python manage.py e2e_reset`.
Expected: the refusal, and the dev book is unchanged.

`feat(accounts): add e2e_reset to prepare the end-to-end test database`

### Task 5: CI job and docs

**Files:**

- [ ] **Step 1: Add the job `e2e` to `ci.yml`**

The job runs in parallel with the other three. It needs no `needs`.

- **Services:** `postgres:18-alpine`, with `POSTGRES_DB: folkbook_e2e`, user and password `folkbook`, port 5432, and the same health check as `backend`.
- **Job env:** `DJANGO_SECRET_KEY: ci-only-not-secret`, `POSTGRES_PASSWORD: folkbook`, `POSTGRES_HOST: localhost`.
- **Steps:**
  1. `actions/checkout@v7`.
  2. `astral-sh/setup-uv@v10.2.0`, with `working-directory: backend` and the cache enabled.
  3. `uv sync --locked` in `backend`.
  4. `actions/setup-node@v7`, Node 22, with the npm cache.
  5. `npm ci` in `frontend`.
  6. Put `npx playwright --version` in a step output.
  7. `actions/cache@v4` on `~/.cache/ms-playwright`, keyed `playwright-${{ runner.os }}-<version>`.
  8. On a cache miss, `npx playwright install --with-deps chromium`. On a hit, `npx playwright install-deps chromium`.
  9. `npm run e2e` in `frontend`.
  10. With `if: failure()`, `actions/upload-artifact@v4`: name `playwright-report`, paths `frontend/playwright-report/` and `frontend/test-results/`, `retention-days: 14`.
